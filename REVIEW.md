# Architecture review

Reviewed the cloned implementation and exercised the local replacement. This review focuses on persistence, annotation integrity, coupling, and avoidable work; it does not evaluate extraction accuracy against a labeled clinical dataset.

## Findings addressed

| Finding in the original code | Impact | Change |
| --- | --- | --- |
| Firebase authentication was required even for manual editing. Firestore, IndexedDB, and localStorage each held different parts of the workspace. | Local startup depended on a hosted project; audio could disappear independently of its session. | Replaced cloud auth/storage with an Express API and one local SQLite database, including audio and settings. |
| Missing keys and failed requests returned generated demo annotations, guessed relations, or a canned transcript with `success: true`. | Synthetic clinical content could be saved into a real annotation session. | Removed automatic demo fallbacks. AI failures now surface as errors. Failed span grounding cannot substitute the first characters of an unrelated utterance. |
| Annotation and relations initialized Gemini before checking the OpenAI configuration. | An OpenAI-only configuration fell into the mock path without contacting its selected provider. | Provider selection now precedes client initialization; tested with a local OpenAI-compatible endpoint and no keys. |
| Export code filled missing metadata with `positive`, `certain`, `current`, `patient`, and `asserted`. | Missing annotation context became clinical assertions in exported datasets. | Missing context remains `unassigned`. |
| The legacy migration treated an empty mentions array as an old record. | Deleting the last mention could regenerate it from the entity's old span. | An explicit empty mentions array is authoritative. |
| Attribute support was a free-text hint on an entity-linked mention; exports and summaries grouped all mentions under the entity. | Text supporting only dosage, onset, or severity also appeared to support the whole entity. | Added stable attribute nodes and explicit entity-or-attribute targets, migration, API validation, separate summaries, per-target context propagation, a case evidence graph, and versioned exports. |
| FHIR symptoms and measurements lacked structured timing. Onset aliases could copy a duration into an event date; workspace creation time was the only session date. | Event time, duration, and documentation time could be conflated or left buried in text. | Added independent clinical encounter time, shared temporal controls/types, symptom onset/resolution/duration and measurement effective time. Preserve legacy wording, validate anchors and partial dates, separate derived calculations from evidence, and remove duration-to-onset aliasing. |
| The notes display adapter synthesized `task` and `title` aliases for every entity. Editing persisted these display-only values as real fields. | Symptom edits silently accumulated unrelated attributes. | Removed fabricated aliases; browser tests verify a value edit does not create extra attributes. |
| Conversation subscriptions depended on the active selection and downloaded the collection again. | Switching sessions rebuilt subscriptions and repeated collection processing. | A workspace hook handles initial loading, incremental write responses, ordered saves, and refresh on tab focus. |
| Group deletion and updates fanned out through sequential client writes. | Partial failures could leave inconsistent group membership; shared schema copies drifted. | Group membership uses a foreign key with atomic detachment on deletion; local views resolve the group directly. |
| Clicking Generate flushed a debounced save but immediately used the previous React props. Empty text did not clear old segments. | AI could annotate stale text; cleared transcripts retained stale segments. | Generate receives and saves the editor's actual text. Empty segment arrays are persisted. |
| Audio was reread and assigned new object URLs after unrelated conversation changes. The graph animation never stopped. | Memory retention, unnecessary reads, and continuous quadratic layout work. | Audio is loaded when the selected recording changes and URLs are revoked. Graph layout has a frame budget and indexed link lookup. |
| Every audio upload was decoded and transcoded, including already compressed small recordings. Recording also automatically started browser speech recognition. | Avoidable CPU/memory use and quality loss, plus an implicit speech-processing path outside provider settings. | Preserve recordings up to 50 MB unchanged. Compression is reserved for oversized inputs; browser speech recognition was removed. |
| Duplicate transcript parsers/default schemas and an unused legacy extraction implementation lived in the server. | Fixes diverged across UI and API; the server carried substantial dead and fallback code. | Reused the shared parser/schema and removed obsolete implementations. |
| Production startup lacked `NODE_ENV=production`; preview served only the frontend; port 3000 and all-interface binding were hardcoded. | Inconsistent startup and a no-login service unnecessarily exposed to the network. | Production runs the full compiled app; configurable port, loopback binding, same-origin API checks, JSON API errors, and shared HTTP/HMR listener. |
| React type definitions were absent and dependencies had 10 reported audit findings. | TypeScript missed component errors; outdated packages remained in use. | Added React types, reconciled supported attribute field types, updated compatible dependencies, and scoped a patched `qs` override to Express. Install audit reports zero findings. |

## Remaining priorities

1. **Finish category/schema validation.** Entities now retain an explicit `categoryId`, populated from their notes category during migration and used preferentially in the UI. Legacy fallback paths in `ClinicalNotesView.tsx` still infer categories with name and type heuristics, and AI extraction often uses the category ID as its biomedical type. Validate membership against a saved schema and keep labels, categories, and biomedical types separate.

2. **Preserve annotation history and schema provenance.** `App.tsx` replaces the annotation on regeneration and resets relations. There is no durable run history, undo, optimistic revision check across tabs, or saved snapshot of the schema/model/prompt used for an annotation. A late AI response can overwrite concurrent curation. Store annotation revisions and AI runs, and require an explicit application step for generated changes. Full JSONL exports should include schema/version provenance; currently even the full-session format omits group schema definitions.

3. **Strengthen grounding and semantic validation.** Extraction now requires a literal source match, but repeated occurrences within an utterance still use the first match. `RawTranscriptView.tsx` and `segmentRealignment.ts` contain additional heuristic recovery paths. Add stable occurrence offsets and tests for repeated words, Unicode, overlapping mentions, splits, deletions, and speaker changes. Evidence validation now checks unique node IDs and attribute ownership, and AI clustering rejects duplicate/unknown mention assignments. Category IDs, context enums, and attribute value types still need complete schema validation.

4. **Separate canonical concepts from contextual statements.** The server and notes view synthesize an entity-level status from its mentions; for example, negative mentions can drive an entity toward a refuted state. One concept can occur in patient versus family history, at different times, or with conflicting certainty. Keep those statements distinct and present the source mentions for any summary. This needs explicit product semantics and a labeled regression dataset, not additional name-based rules.

5. **Split the large modules around domain responsibilities.** `App.tsx` still coordinates editing, AI calls, export, and multiple dialogs. `ClinicalNotesView.tsx` is approximately 2,900 lines and combines forms, category inference, mention aggregation, UMLS calls, and repair logic. Move domain transformations into tested functions, provider calls into adapters, and dialogs into components. Several group settings such as preferred model/template/taxonomy are exposed in the UI but are not consistently consumed by generation; define their precedence or remove ineffective controls.

6. **Scale loading and expensive work deliberately.** The local API still returns every conversation JSON document at startup/focus, and writes send whole annotation objects. SQLite operations are synchronous. That is suitable for a small personal workspace; large corpora need paginated summaries, on-demand session loading, and perhaps a database worker. Graph repulsion remains O(n²) while active even though it now stops. Oversized audio compression still decodes the entire recording into memory.

7. **Make AI jobs cancellable and observable.** OpenAI-compatible HTTP requests now have an abort timeout, but the generic `withTimeout` helper does not cancel Gemini work. Batch retries treat many failures alike, and requests/run state are not durable across a server restart. Separate retryable provider errors from invalid credentials/schema responses; record per-stage status and timing; add cancellation and interrupted-job recovery. Audio-derived timestamps are estimates, and speaker inference from Whisper text is not true audio diarization.

## Verification and limits

Automated checks exercise database reopening, custom schema/context preservation, audio cleanup, validation, login-free CRUD, origin/host restrictions, missing credentials, OpenAI routing, and failure behavior. The Chrome workflow creates a real manual span annotation, reloads it, follows a local link, downloads JSONL, and checks the exported mention and entity linkage without any external browser requests.

No paid Gemini/OpenAI service, real microphone device, UMLS account, large corpus, or existing Firebase export was exercised. Existing cloud data has not been migrated. Local settings and recordings are stored as plaintext database content, and concurrent users are outside this no-login configuration's scope.
